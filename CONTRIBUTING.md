# Contributing to Open MelMe

## Welcome
Thanks for your interest in contributing. Open MelMe is still early-stage, and help is welcome across bug fixes, improvements, documentation, performance work, and feature suggestions. If you want to collaborate, you are in the right place.

## Before Contributing
- Check open issues first and look for existing discussions.
- Avoid duplicate work by coordinating on a related issue.
- Discuss major changes before implementation to align on direction.

## Reporting Bugs
Please include:
- A clear description of the problem
- Steps to reproduce
- Screenshots or logs if helpful
- Expected behavior vs actual behavior

## Suggesting Features
Please include:
- The problem you are trying to solve
- Your use case or target user
- Why the change is useful

Avoid vague requests. Concrete proposals help the project move faster.

## Improving Documentation
Documentation improvements are highly appreciated. If something is unclear or outdated, fixing it helps everyone.

## Pull Request Process
1. Fork the repository
2. Create a branch for your change
3. Make focused, minimal changes
4. Commit with clear messages
5. Open a PR describing the change and why it helps

Please keep PRs focused and avoid unrelated refactors. Larger architectural changes should be discussed before starting.

## Development Expectations
- Follow the existing architecture
- Maintain clean, readable code
- Keep patterns consistent with the current codebase
- Avoid unnecessary complexity

## Community Expectations
We value respectful communication, constructive feedback, and a collaborative environment.
